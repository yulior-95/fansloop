用户体验与信息架构（摘要）

1. 体验目标：创作者在 Web 端完成「资产查看 → 链上充值 / 钱包提现 → 充提记录核对 → 异常申诉」闭环；减少法币双通道带来的认知负担，当前原型收敛为钱包 · 所选网络单一主路径。 2. 核心交互：充值页隐藏 Tab 但保留法币节点；提现主入口 withdraw-fiat.html 默认展示链上提现（法币表单整段隐藏可恢复）；充提记录仅展示「入账中 / 已到账」与网络费用列，筛选「处理中 / 已完成」与之映射。 3. 合规 KYC：链上提现提交前仍走 KYC 弹窗与向导（与既有 localStorage 模拟一致）。 4. 帮助形态：MoonPay 买币 / 卖币教程以当前页全屏遮罩弹窗呈现，配图使用 Unsplash 可商用摄影，便于视觉与前端对齐布局。

KYC 身份验证与提现门槛

核心逻辑：默认未验证；用户上传身份证正反面 → 三方联网核查 → 人脸识别（可生成手机链接）→ 提交后状态为「审核中」；后台机审或人工回传通过/不通过，不通过时展示原因并允许重新发起；通过后个人资料展示实名标签。 提现：主路由 withdraw-fiat.html 现为「钱包提现」默认视图（法币 DOM 整段隐藏可恢复）；withdraw-usdt.html 双 Tab 隐藏。两页提交前均校验 KYC。 后台：admin-prototype/kyc-manage.html 列表 + kyc-detail.html 材料与处置（与 kyc-admin-list.html 共用 localStorage）。
