1. 本次主题与改动概览

7/18 及之前几版的主体是资金链路（钱包双账户、稳定币充提、划转、风控）。 本次完全切换到内容侧：把发现页写死在前端的 12 个平铺分类， 升级为「后台可维护的三级类目树 + 用户端只露一级 + 创作端必选三级」的完整链路， 并为热门频道补上了一份可落地的推荐算法规格书。

3. 发现页 · 一级频道 Tab 改造 改造

页面： pages-web/discover.html
逻辑： js-web/discover-taxonomy.js（v4→v5） · js-web/discover-page.js（v7→v8）

主要调整

  • Tab 数据源由内部硬编码数组改为 FL_CONTENT_TAXONOMY.getLevel1()，只渲染一级
  • 默认选中项由 all 改为 hot；all 保留为别名，旧链接 ?category=all 仍可打开
  • URL 同步逻辑跟着改：选中热门时删除 category 参数，其余写入一级 id
  • 接入 onChange 监听——运营在后台改类目后，发现页 Tab 与内容列表实时刷新，无需重载
  • 当前选中的类目被后台停用/删除时，自动回落到热门，不会出现空白 Tab

内容归类逻辑

Post 数据模型从「一个 categories 数组」升级为双字段：

categoryId:      'photo-art'   // 创作者选的三级叶子，落库主字段
primaryCategory: 'visual'      // 由 rootIdOf(categoryId) 推导，用于 Tab 筛选
  • resolveContentCategory() 判定优先级：创作者选的三级 > hashtag 映射 > 兜底
  • HASHTAG_MAP 全量重挂到新的叶子 id（如 旅行摄影 → travel-log、日出 → photo-art）
  • 演示数据从 12 条扩到 17 条，补齐沉浸体验、情感关系、互动时刻等新频道，避免切 Tab 出现空列表

页面内批注同步

发现页「推荐规则」玻璃批注新增一条：Tab 只取后台三级类目树的一级；二三级仅用于归类与推荐。

热门频道的特殊规则

  • 热门标记为 system: true，不可删除、不可停用
  • 其下「热门推荐 / 新鲜发现」可以维护子级——它们是推荐算法的投放位
  • 下钻到热门时，面包屑旁出现黄色提示条：该频道下的类目为推荐算法投放位，由算法按热度与新鲜度填充，创作者发布时不可选择
  • 页面顶部规则卡同步写明这条约定，避免运营误把热门当普通归类频道使用

5. 创作页 · 内容类别三级单选抽屉 新增

页面： pages-web/create.html
样式 / 逻辑： css-web/create-category.css · js-web/create-category-select.js · js-web/create-studio.js

入口

图文动态（#panelImage）与视频作品（#panelVideo）两个编辑面板各插入一个类别字段，标注「必选」。未选择时显示占位文案「选择内容类别（需精确到三级）」，选中后显示完整三级路径。

抽屉交互

  • 三列联动：一级 → 二级 → 三级，只有点到三级才算选中
  • 顶部搜索框可直接搜三级类目（如「人像写真」「链上科普」），命中后单列结果展示完整路径
  • 底部实时预览已选路径，配「清空 / 确认选择」两个动作
  • 图文与视频各自独立记忆选择结果，切换内容类型不串台
  • 一级列表过滤掉 system: true，因此热门及其 5 个算法位创作者选不到

与发布流程打通

环节行为
发布校验requireCategory(type)：未选类别时弹 Toast「请先选择内容类别（需精确到三级）」并自动打开抽屉，阻断发布
成功提示提交成功文案追加「已归类到「视觉美学 / 写真摄影 / 艺术写真」。」
草稿categoryId 写入草稿 payload，重新进入编辑器自动回填
预览预览卡新增蓝色类别徽章 .pm-badge.cat，与免费 / 订阅 / PPV 徽章并列
待审内容待审列表的预览按钮补 data-category，预览时展示该内容自己的类别而非当前编辑态
被去掉的内容：两个面板下方原有的说明文字「类目由平台统一维护；用户端只展示一级频道，二三级用于精准推荐与审核分流。」按反馈移除，对应的 .cat-field-hint 样式一并删除。

6. 热门频道推荐算法规格书 新增文档

文档： docs/hot-channel-ranking-spec.html

热门频道的 5 个投放位不是内容归类，需要算法定义。本文档在原始草案基础上做了修正与补全，共 14 节。

对原草案的关键修正

槽位原草案问题修正
今日热门 播放增速（量级 10³）与完播率（0~1）直接加权相加，其余 70% 权重形同虚设；互动率含收藏分享，与后两项重复计算 统一走同类目百分位归一化；互动率口径收窄为点赞/评论/弹幕/打赏，保留原 30/30/20/10/10 权重
爆款视频 累计播放量 + 五个率 无权重相加，实际等价于按播放量排序；无时间窗，老爆款永久霸榜 播放量改为「门槛项 + 对数压缩弱权重」；新增传播系数 K 与破圈率；30 天窗口 + 单条 7 天占位上限
高互动 点赞/评论/收藏/分享等权相加；打赏、订阅、付费解锁等平台核心信号完全缺失；无最小样本 差异化权重表（点赞 1 → 订阅 40）；UV ≥ 300 门槛 + 贝叶斯平滑；新增评论健康度与争议内容识别
新创作者 OR 条件致命：三年老号 50 万粉丝只要「作品 < 10」就能占新人位 改为 AND；「注册时间」换成「首次发布时间」；补合规门槛、潜力排序、保量扶持与毕业机制
最新发布 审核状态、用户举报被当作打分项相加，等于「没过审扣点分但还能展示」 两项移为硬门槛；时间权重提到 0.70，保证「最新」名副其实

新增的通用机制

  • 统一三段式打分：Σ(权重 × norm(因子)) × decay × penalty × trust × access
  • 归一化：同期同类目百分位，计数型指标先做 log(1+x) 压缩
  • 小样本平滑：贝叶斯平滑（α=200），杜绝「5 播放 5 互动 = 100%」霸榜
  • 时间衰减：五个槽位分别定义半衰期（2h ~ 72h）
  • 负反馈：不感兴趣 / 秒退 / 举报 / 拉黑，惩罚上限 60%
  • 反作弊信任分：七项检测（增速异常、互动集中、新号占比、IP 聚集等）
  • 多样性：同创作者上限、跨槽位去重优先级、类目 MMR 打散、候选不足兜底链路
  • 付费降权：access = 0.55，与现有 discover-access.js 保持一致
  • 另含数据字段与埋点清单、接口契约、刷新频率、A/B 方案与 14 项验收清单
