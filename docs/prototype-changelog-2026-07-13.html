1. C 端 · 首页 A/B 测试 · 方案 B（沉浸 Feed）

页面： pages-web/home-ab-feed.html
逻辑 / 样式： js-web/home-ab-feed.js · js-web/feed-ab-stack-builder.js · css-web/home-ab-feed.css

独立路由，不影响现有 home.html（方案 A）。顶栏提供「方案 B · 切至 A」入口；localStorage 记录 fl_home_ab_variant=b。

交互要点

  • 抖音 Web 风全屏竖滑 Feed：推荐 / 关注 / 直播三 Tab
  • 元信息叠加于内容四角（创作者、标题、互动按钮）
  • 右侧操作栏：点赞、评论、收藏、分享、订阅
  • 直播卡片带「直播中」标识，点击进入直播详情
  • 首次进入下滑提示、滚动进度条、新内容 Hint

2. C 端 · 直播详情 A/B 测试 · 方案 B（沉浸简约）

页面： pages-web/live-detail-ab.html
逻辑 / 样式： js-web/live-detail-ab.js · js-web/live-detail-cohost.js · js-web/live-view-host.js · css-web/live-detail-ab.css

独立路由，不影响 live-detail.html（方案 A）。默认演示 ?host=yeyu；顶栏可切回方案 A。

  • 右下角观众连麦席位（ldAbAudienceSlots）：48px 头像、纵向 2 席、说话白色声纹

  • 主播连麦进行中时隐藏观众上麦入口；PK 血条底栏薄条样式
  • 实时字幕、礼物动效、分享、关注、打赏等沉浸交互保留

样式： css-web/live-host.css

在保留全部功能按钮的前提下，优化一屏信息密度与模块分区，避免右侧栏过长滚动。

新布局结构

区域内容
左侧主列推流舞台（上）+ 连麦&PK | 礼物动态（下，双列）

  • 移除顶栏「返回工作室」按钮（侧栏「创建内容」仍可返回）
  • 响应式：<1100px 改为单列堆叠

5. 主播控制台 · 连麦 / PK / 观众上麦（可交互原型）

逻辑： js-web/live-host-cohost.js · css-web/obs-cohost-pk.css

工具栏

  • 随机匹配 · 指定连麦 · 观众上麦 · 发起 PK（需先完成主播连麦）
  • 互斥规则：主播连麦与观众上麦不可同时开启；一方进行中时另一方入口置灰并提示
  • To 研发气泡补充完整规则列表（合流、PK 计分、退出逻辑等）

舞台注入

  • 连麦成功：2/3 路分屏 + 顶部连麦条 + 舞台内退出连麦按钮（host-cohost-exit-stage）
  • PK 进行中：底部薄条血条 obs-pk-hud--dock，主播昵称标签上移避挡
  • 连麦顶栏与 LIVE 顶栏分行（top: 52px），避免标签重叠

观众上麦 · 舞台席位（7/13 新增）

  • 开启观众上麦后，舞台右下角立即显示 2 个空席（对齐 ldAbAudienceSlots 样式：48px 头像）
  • 同意申请 → 首席显示观众头像 + 声纹；踢下麦 → 恢复空席
  • 关闭观众上麦 → 移除席位 DOM
  • 席位定位 bottom: 58px; right: 12px，避开底部控制条

指定连麦弹窗

  • 文案：「搜索正在直播且可连麦的主播」
  • 红点改为 obs-host-live-dot，表示「直播中」而非「可连麦」
