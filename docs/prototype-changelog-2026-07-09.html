2. C 端 · 直播详情页 · 观众申请上麦（演示页）

页面： pages-web/live-detail.html
逻辑： js-web/live-detail.js · css-web/obs-cohost-pk.css

本页作为允许上麦的交互优化演示直播间；其他 obs-cohost-pk 子页面未改动。

功能要点

  • 操作栏「申请上麦」旁增加 To 研发 气泡：说明按钮仅在主播开启允许申请上麦时展示
  • 播放器右下角展示 2 个连麦空席（obs-audience-slots）
  • 状态流转：点击申请 → 等待主播同意… → 默认约 2.8s 后进入连麦
  • 连麦成功：按钮变「连麦中」、聊天侧栏出现上麦条（静音 / 下麦）、首个席位显示观众头像
  • 拒绝模拟：URL 加 ?micOutcome=reject → 顶部横幅 + Toast「主播拒绝您的申请」

研发备注

默认同意：live-detail.html
模拟拒绝：live-detail.html?micOutcome=reject

4. 运营后台 · 筛选栏 Select 下拉无法展开（修复）

逻辑： admin-prototype/js/admin-form-controls.js

根因：<label class="ord-filter-item"> 包裹增强 Select 时，浏览器会将 click 转发给隐藏的原生 <select>，导致下拉刚打开即被第二次 toggle 关闭。

修复方式

  • 改用 mousedown 切换下拉（左键）
  • 父级 label 捕获阶段 preventDefault，阻止转发
  • 影响范围：所有使用 AdminFormControls 增强的筛选工具栏（提现 / 订阅 / 充值订单等）

6. 运营后台 · 提现人工审核流程（新增）

页面： admin-prototype/orders-withdraw.html
逻辑： admin-prototype/js/orders-withdraw-page.js · css/orders-list.css

规则对齐 risk-usdt-limits.html 充提限额：单笔 ≤ 10,000 / 单日累计 ≤ 50,000 USDT；单笔 ≥ 500 USDT 提交成功后进入人工审核。

新增状态「审批中」

  • 筛选器增加 审批中 选项
  • 表格状态列橙色标签展示
  • 样例：500 USDT、1000 USDT 两笔为审批中；300 USDT 为处理中

操作列

  • 「错误描述」右侧新增操作列（右侧 sticky）
  • 仅「审批中」订单显示 审核 按钮；点击行仍可打开详情

审核弹窗

按钮结果
确认状态 → 处理中，进入原有链上打款流程
拒绝状态 → 失败；错误描述：人工审核拒绝：{备注}（无备注时为「人工审核拒绝」）
