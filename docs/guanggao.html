一、项目背景与建设目标

在现有直播社交平台中增量建设广告能力，不重建产品、不改动无关模块。支持广告主自主投放与平台运营投放，共用审核、投放、展示与统计。

一期采用固定套餐（按广告位 + 购买周期收费），广告主须申请资质并审核通过后方可购买套餐并发布付费广告。原型使用模拟数据；支付、审核、投放、到账等未接入真实服务处均在交互中标注为演示。

八、业务流程图

8.1 总览（资质 · 创编 · 审核 · 投放）

【广告主资质】
  申请 → 后台审核 → 通过(approved) / 驳回 → 修改后重提

【用户广告】
  创编 → 选套餐 → 余额? → 不足:充值(模拟) / 足够:payOrder(幂等) → submitForReview

【平台广告】
  运营创建 → 权限? → 普通:待审核 / 授权:安全检查后发布

【汇合】
  内容审核 → 驳回:回创编 / 通过 → 到开始时间? → 否:pending_start / 是:delivering
  delivering → 三端展示 → 统计(曝光/点击/转化模拟)
  delivering → 暂停/恢复 / 下架结束 → 退款(规则待业务确认)

8.2 用户自主 vs 运营（汇入点）

两条发布路径均在内容审核与支付/投放条件处汇合；平台广告 payStatus 可为 none，用户广告必须 paid 方可进入投放链。

九、状态定义（分字段维护）

UI 可组合展示（如「审核通过 · 待开始」），底层不得混为单一状态。

域枚举（代码键）
审核draft · pending_review · approved · rejected · revoked
支付unpaid · processing · paid · failed · refund_processing · partial_refunded · refunded · refund_failed · none（平台）
投放pending_start · delivering · paused · ended · removed
广告主账号pending · approved · rejected · restricted · disabled

9.1 状态转换限制（摘要）

  • 未支付 → 不可提审、不可投放。
  • 未审核通过 → 不可投放。
  • 驳回 → 须修改后重审，不可直接开播。
  • 审核通过后修改素材/文案/落地链 → 新版本 + pending_review，旧通过状态不延续。
  • ended / removed → 不可直接恢复投放（需新建广告或新业务规则，待确认）。
  • 退款总额 ≤ 订单可退金额；重复退款请求幂等。
  • 账号 restricted / disabled → 不可创建或恢复投放。
  • 不允许的操作由 API 返回 明确中文原因（js/ad-system-api.js）。

9.2 资金字段

区分：可用余额、冻结、已消费、已退款；订单 应付/实付/累计已退/当前可退。一期套餐为一口价，不按曝光/点击动态扣费。

暂停：停止展示，一期原型不自动退款；恢复时校验资质、审核版本、周期与支付。
退款：未支付订单可取消；已付未开始可申请退款（比例与时效待业务确认）；已投放主动下架不自动全额退。

十、统计、风控与审计

  • 统计：曝光、点击、CTR；进房等转化仅展示可追踪且原型标注为模拟的数据；异常点击在 risk 中标记，不计入有效效果（演示口径）。
  • 风控：素材/链接风险、异常点击、举报；支持暂停/下架/限制广告主。
  • 审计：关键操作写入 opLogs；资金流水只追加，运营不可改删（原型）。

十二、交互与安全异常（原型覆盖）

场景预期行为
越权改套餐价非 super 角色拦截并提示
恶意链接 / 不合规 URL提交拦截并说明
重复点击支付/退款幂等，不重复扣款

危险操作二次确认（confirm / AdminModal）
审核驳回必填原因；广告主可见并重提

十五、待业务确认事项

以下影响研发与财务方案，不得写死为已确定规则；原型中用配置项或「待业务确认」文案占位。

  1. 广告主准入材料与 KYC 是否复用现有实名体系。
  2. 已投放订单主动下架/违规下架的退款比例、时效、到账方式。
  3. 转化事件（进房等）的统计口径与去重规则。
  4. 直播间广告频次上限与仅运营可投是否长期成立。
  5. 运营免人工审核白名单范围与安全校验清单。
  6. 地域/语言定向以平台真实可用数据为准的最终列表。
  7. 真实支付通道、对账与发票流程。
